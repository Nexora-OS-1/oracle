Designed to stay close

Your system details stay on your system.

ORACLE reads system information through Windows APIs and inspects only the files you choose. Its source includes no account flow, telemetry integration, or remote analysis service. Settings are stored locally.

When you download ORACLE, your browser requests the package from the website host. The application itself does not need an account or a cloud service to inspect your PC.

Local by design
  • Process details read from Windows
  • File previews stay in the app
  • Refresh preference stored on this PC
  • No account or remote analysis service

A few helpful answers

Good to know.

Does ORACLE change or stop processes?

No. The app provides read-only inspection. It does not terminate processes, change Windows settings, install a service, or request administrator privileges.

Is LENS a malware scanner?

No. LENS displays bounded text previews, simple keyword matches, and basic executable version metadata. It is not a full malware scanner and should not replace security software.

Will ORACLE run the code I put in LAB?

No. LAB is a text editor for snippets. Code execution and OS-isolated sandboxing are unavailable.

Why might process details be missing?

Some processes exit while the list is refreshing, and Windows may restrict access to another process’s executable path. ORACLE labels unavailable fields and records relevant app messages.

Windows says the app is unrecognized. Is it signed?

No. ORACLE is not signed with a code-signing certificate. Windows SmartScreen may show a warning for unsigned software. The SHA-256 checksum above helps compare the downloaded package with the published file; it is not a signature or a malware verdict.

What if Windows reports a missing runtime?

The release package is self-contained and includes the .NET Desktop runtime files. If Windows still reports a runtime issue, make sure you extracted the entire ZIP and launched ORACLE.exe from the extracted folder.
